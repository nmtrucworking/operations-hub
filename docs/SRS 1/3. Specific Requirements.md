## 3.1. Functional Requirements 
Mô tả chi tiết các chức năng hệ thống.
Thường được trình bày dưới dạng:
- Use case
- User Story
- Requirement ID (FR-01, ...)
- Input - Process - Output

Ví dụ cấu trúc: 

| ID  | Mô tả | Input | Xử lý | Output |
| --- | ----- | ----- | ----- | ------ |
|     |       |       |       |        |

Yêu cầu chức năng mô tả các hành vi và dịch vụ mà Operations Hub phải cung cấp. Các yêu cầu này được phân tích từ 21 nhóm use case thuộc phạm vi sản phẩm tổng thể. Tuy nhiên, việc một use case nằm trong phạm vi sản phẩm không đồng nghĩa toàn bộ chức năng của nhóm đó phải được hiện thực trong đô án cơ sở

Bảng: Phân chia phạm vi chức năng

| Mức phạm vi                         | Nội dung                                                                                                                                                  |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Phạm vi sản phẩm tổng thể           | Bao gồm toàn bộ 21 nhóm useCase của Operations Hub, từ năng lực nền tảng đến các module vận hành chuyên môn                                               |
| Phạm vi phân tích                   | Các nhóm use case tổng thể được nhận diện, mô hình hóa và duy trì khả năng truy vết để làm cơ sở phát triển tiếp                                          |
| Phạm vi hiện thực trong đồ án cơ sở | Ưu tiên tài khoản, đăng ký tổ chức, khởi tạo tenant, quản trị tổ chức, cơ cấu, membership, vai trò, quyền, branding, cấu hình module và nhật ký hoạt động |
| Phạm vi kiểm thử nghiệm thu         | Các yêu cầu `Must` được đánh dấu thuộc baseline hiện thực, phải có test case và minh chứng kết quả                                                        |
| Phạm vi hoãn                        | Các module chuyên sâu chưa được hiện thực đầy đủ phải được đánh dấu Deferred, không được trình bày như chức năng đã hoàn thành                            |
